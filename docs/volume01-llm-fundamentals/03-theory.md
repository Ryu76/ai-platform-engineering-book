# LLM 기초: 핵심 이론

## 1. Token과 Context Window

토큰(Token)은 모델이 읽고 생성하는 단위입니다. 한글 글자 수나 단어 수와 일대일로 같지 않습니다. 입력 메시지, 시스템 지시문, 검색 문서, 도구 결과와 모델 출력은 모두 토큰 예산을 사용합니다.

컨텍스트 윈도우(Context Window)는 한 요청에서 모델이 함께 고려할 수 있는 토큰의 최대량입니다. 입력이 길어질수록 출력에 쓸 공간이 줄어들 수 있습니다.

```text
System 메시지 + User 메시지 + 검색 문서 + 도구 결과 + 출력
                         └──── 컨텍스트 윈도우 안에 들어가야 함 ────┘
```

## 2. 메시지 역할

| 역할 | 책임 | 예시 |
|---|---|---|
| System | 서비스의 지속 규칙 | "근거가 없으면 모른다고 답하세요." |
| User | 현재 요청 | "이 문서를 세 문장으로 요약해줘." |
| Assistant | 앞선 모델 응답 | 대화 문맥의 이전 답변 |

System 메시지는 사용자 입력보다 신뢰할 수 있는 서비스 정책을 전달하는 곳입니다. 외부 문서나 사용자 입력에 포함된 지시문은 System 정책을 바꾸지 못하도록 분리합니다.

## 3. 생성 파라미터

- **Temperature**: 값이 높을수록 다음 토큰 선택이 다양해질 수 있습니다. 정답 형식이 중요한 추출 작업은 낮게 시작합니다.
- **Top-p**: 누적 확률 범위 안에서 후보를 제한합니다. Temperature와 동시에 과도하게 조절하지 말고 한 변수를 먼저 비교합니다.
- **Max output tokens**: 출력 상한입니다. 비용과 지연 시간을 제한하지만 너무 낮으면 문장이 중간에 끝날 수 있습니다.

## 4. Hallucination과 최신성

모델은 학습 시점 이후 정보를 모르거나, 근거 없이 내용을 만들어 낼 수 있습니다. 이를 해결하려면 질문에 맞는 문서를 검색하고, 문서 범위 안에서 답하도록 만드는 RAG가 필요합니다.
