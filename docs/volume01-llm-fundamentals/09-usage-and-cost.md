# 토큰 사용량과 비용 추정

## 1. 학습 목표

이 장을 마치면 입력 토큰(input tokens)과 출력 토큰(output tokens)을 구분해 기록할 수 있습니다. 제공자가 반환한 사용량과 사람이 확인한 가격표를 `Decimal`로 계산하고, 작업별 비용 상한을 초과한 추정을 안전하게 중단할 수 있습니다. 또한 정확한 청구 금액, 사전 추정, 실제 사용량의 차이를 설명할 수 있습니다.

## 2. 왜 필요한가

LLM 호출은 요청 본문 크기만으로 비용을 판단하기 어렵습니다. 시스템 프롬프트, 대화 이력, 검색 문서가 입력 토큰에 함께 포함되고, 모델이 생성한 답변은 출력 토큰으로 별도 과금될 수 있습니다. 긴 RAG 문맥과 반복 재시도는 사용량을 빠르게 늘릴 수 있습니다.

AI 업무 처리 플랫폼은 호출이 성공했는지뿐 아니라 어느 모델이 입력·출력 토큰을 얼마나 썼는지 기록해야 합니다. 이 장은 제공자 청구서를 대체하지 않습니다. 외부 네트워크 없이 `LlmResponse.usage`를 비용 추정으로 바꾸는 작은 경계를 먼저 만들고, Volume 10에서 작업별 지연 시간·토큰·비용 평가 리포트로 확장합니다.

## 3. 핵심 개념

**입력 토큰**은 모델에 보낸 메시지와 시스템 지시문 등의 토큰입니다. **출력 토큰**은 모델이 생성한 답변의 토큰입니다. `LlmClient.complete()`은 OpenAI Chat Completions 호환 응답의 `prompt_tokens`, `completion_tokens`를 `TokenUsage(input_tokens, output_tokens)`로 변환합니다.

**가격표(pricing)** 는 보통 입력·출력 각각의 100만 토큰당 가격으로 제공됩니다. `ModelPricing`은 이 두 값을 `Decimal`로 받습니다. 통화 금액에 `float`를 사용하면 이진 부동소수점 오차가 누적될 수 있으므로, 이 프로젝트는 금액 계산에 `Decimal("2.50")`처럼 문자열로 만든 `Decimal`만 허용합니다.

계산식은 다음과 같습니다.

```text
입력 비용 = 입력 토큰 × 입력 100만 토큰당 가격 ÷ 1,000,000
출력 비용 = 출력 토큰 × 출력 100만 토큰당 가격 ÷ 1,000,000
총 추정 비용 = 입력 비용 + 출력 비용
```

`CostBudget.require_within()`은 계산한 총 비용이 지정한 상한보다 큰지 확인합니다. 같은 통화끼리만 비교합니다. 이는 **기록된 사용량 또는 보수적으로 추정한 사용량의 검사 도구**입니다. 이미 원격 모델이 답변을 생성한 뒤 받은 실제 사용량으로 검사하면 그 호출 비용을 되돌릴 수 없습니다.

> [!WARNING]
> `CostBudget`은 제공자의 청구 한도나 결제 차단 기능이 아닙니다. 호출 전 강한 상한이 필요하면 제공자가 제공하는 사용 한도·프로젝트 예산을 별도로 설정하고, 입력 토큰 수와 `max_output_tokens`의 보수적 상한을 계산해 요청 전에 검사해야 합니다. 모델별 토크나이저와 가격은 바뀔 수 있으므로 제공자 공식 가격표와 청구서를 기준으로 갱신합니다.

> [!NOTE]
> 스트리밍 제공자가 마지막 이벤트에 사용량을 보내지 않으면 `StreamChunk.usage`는 `None`일 수 있습니다. 이때 0 비용이라고 기록하지 말고 `사용량 미수신`으로 구분합니다.

## 4. 동작 구조

```text
OpenAI 호환 응답 또는 기록된 사용량
             │
             ▼
TokenUsage(input_tokens, output_tokens)
             │
             ├── ModelPricing(입력/출력 100만 토큰당 Decimal 가격)
             ▼
estimate_cost(...)
             │
             ▼
CostEstimate(입력 비용, 출력 비용, 합계, 통화)
             │
             ├── 상한 이하 ───────────────► 기록·다음 작업 진행
             └── 상한 초과 ───────────────► CostBudgetExceeded로 중단·검토

Mock TokenUsage + 고정 가격표 ─► 외부 API·네트워크 없이 계산 계약 검증
```

## 6. 단계별 실습

### 6.1 고정 사용량으로 비용 계산 실행

```bash
# 실행 위치: WSL Ubuntu 또는 Linux 터미널, 저장소 루트
python examples/volume01/usage_and_cost.py
```

예제의 가격은 학습용 고정값입니다. `1200` 입력 토큰, `300` 출력 토큰과 입력 100만 토큰당 `2.50 USD`, 출력 100만 토큰당 `10.00 USD`를 사용합니다. 실제 모델의 가격으로 간주하지 않습니다.

### 6.2 가격표와 사용량을 명시적으로 연결

`examples/volume01/usage_and_cost.py`의 핵심은 다음과 같습니다.

```python
from decimal import Decimal

from ai_platform.llm import CostBudget, ModelPricing, TokenUsage, estimate_cost

pricing = ModelPricing(
    input_per_million_tokens=Decimal("2.50"),
    output_per_million_tokens=Decimal("10.00"),
    currency="USD",
)
usage = TokenUsage(input_tokens=1200, output_tokens=300)
estimate = estimate_cost(usage, pricing)
CostBudget(maximum_cost=Decimal("0.01"), currency="USD").require_within(estimate)
```

`Decimal("2.50")`은 정확한 십진 금액을 표현합니다. 가격·예산이 음수, `NaN`, 무한대이거나 통화가 세 글자 대문자가 아니면 `UsageConfigurationError`가 발생합니다. 상한보다 큰 추정은 `CostBudgetExceeded`로 구분합니다. 호출 코드에서는 이 예외를 잡아 다음 Agent 단계나 고비용 모델 선택을 중단하고 사람에게 검토를 요청할 수 있습니다.

### 6.3 네트워크 없는 계산·예산 테스트

```bash
# 실행 위치: WSL Ubuntu 또는 Linux 터미널, 저장소 루트
pytest tests/unit/test_usage.py -q
```

테스트는 `Decimal` 계산으로 입력·출력 비용을 분리하고, 상한과 정확히 같은 비용은 허용하며, 상한 초과와 통화 불일치는 거부하는지 확인합니다. 전송 계층이나 실제 API 키를 만들지 않습니다.

### 6.4 실제 응답 사용량을 기록할 때의 연결 지점

라이브 호출을 선택한 경우에만 이미 존재하는 응답의 사용량을 같은 함수로 계산할 수 있습니다. 이 코드는 가격표를 사람이 최신 값으로 확인한 뒤에만 사용합니다.

```python
response = client.complete(messages)
estimate = estimate_cost(response.usage, pricing)
# estimate.total_cost와 response.model을 키·프롬프트 원문 없이 기록
```

`response.usage`가 0이라면 무료 호출로 결론 내리지 않습니다. 제공자가 사용량을 반환하지 않았거나 호환 형식이 다른지 먼저 확인합니다.

## 7. 코드 설명

`estimate_cost()`는 `TokenUsage`의 두 값이 0 이상의 정수인지 검사한 뒤, 각 값에 100만 토큰당 가격을 곱합니다. `CostEstimate`는 입력 비용·출력 비용·합계를 분리하므로 출력 토큰 증가가 비용에 미치는 영향을 확인할 수 있습니다. 함수는 네트워크, 환율 조회, 반올림을 수행하지 않아 테스트 결과가 항상 같습니다.

`ModelPricing`과 `CostBudget`은 `Decimal`과 대문자 세 글자 통화 코드를 검증합니다. 서로 다른 통화를 숫자로 직접 비교하면 환율이라는 숨은 가정이 들어가므로 `CostBudget.require_within()`은 통화가 다르면 실패합니다. 환율 변환은 별도 데이터 출처·시점·반올림 정책이 필요한 운영 기능이므로 이 기초 모듈에 넣지 않습니다.

## 8. 정상 실행 결과

고정 예제의 정상 출력은 다음과 같습니다.

```text

13 passed
```

## 9. 오류 해결

| 증상 | 원인 확인 | 해결 |
|---|---|---|
| `... must be a Decimal` | 가격 또는 예산을 `float`나 문자열로 전달했습니다. | `Decimal("2.50")`처럼 문자열에서 만든 `Decimal`을 사용합니다. |
| `... must be a finite nonnegative Decimal` | 음수, `NaN`, `Infinity` 가격·예산입니다. | 제공자 가격표를 다시 확인하고 0 이상의 유한한 값을 설정합니다. |
| `estimate currency must match budget currency` | USD 추정과 KRW 예산처럼 서로 다른 통화를 비교했습니다. | 같은 통화만 비교하거나, 출처·시점·반올림을 명시한 별도 환율 변환 모듈을 설계합니다. |
| `CostBudgetExceeded` | 기록 또는 보수적 추정 비용이 상한보다 큽니다. | 문맥·출력 상한·모델 선택을 줄이고, 승인된 예산 정책을 검토합니다. 예외를 무시하지 않습니다. |
| 사용량이 모두 0 | 제공자가 사용량을 생략했거나 응답 형식이 다릅니다. | 0 비용으로 기록하지 말고 제공자 응답·계측 정책을 확인합니다. |

## 10. 응용 실습

1. 두 가격표를 `ModelPricing`으로 만들고 동일한 `TokenUsage`에서 출력 토큰 가격이 총 비용에 미치는 영향을 비교합니다. 가격 값의 출처와 확인 날짜는 개인 노트에 기록합니다.
2. `GenerationParameters.max_output_tokens`를 바탕으로 보수적인 출력 토큰 상한을 정하고, 입력 토큰 추정치와 함께 `CostBudget` 검사에 전달하는 함수를 설계합니다. 실제 토크나이저 결과와 차이가 날 수 있는 이유를 적습니다.
3. 호출마다 모델명, 입력·출력 토큰, 추정 비용, 통화, 사용량 수신 여부만 남기는 로그 스키마를 작성합니다. API 키와 사용자 원문은 포함하지 않습니다.

## 11. 실무 적용

운영 서비스는 제공자별 모델명·가격표 버전·가격 확인 시점을 함께 관리해야 합니다. 캐시 읽기, 배치 할인, 지역, 세금, 입력 종류에 따라 청구 규칙이 다를 수 있으므로 이 예제의 단순 계산을 실제 청구서와 동일하다고 가정하지 않습니다. 통화별 예산은 같은 통화 안에서 비교하고, 환율이 필요하면 별도의 승인된 데이터 원본과 감사 가능한 변환 정책을 둡니다.

여러 Agent가 하나의 작업을 수행하면 각 호출의 추정치를 작업 ID 단위로 합산하고, 다음 호출 전에 남은 예산을 계산합니다. RAG 문서 수·청크 크기, 재시도 횟수, 출력 상한, Router의 모델 선택은 모두 비용에 영향을 줍니다. Volume 08의 비용 기반 라우팅과 Volume 10의 평가 리포트는 이 사용량 계약을 이어받습니다.

## 12. 과제

- **기본:** 입력 토큰과 출력 토큰이 서로 다른 가격을 가질 수 있는 이유를 설명합니다.
- **응용:** 실제 사용량을 받은 뒤 예산 초과를 발견하는 것과 호출 전 보수적 상한을 검사하는 것의 차이를 설명합니다.
- **심화:** 여러 Agent의 누적 비용 상한을 원자적으로 예약·해제하는 저장 구조와 동시성 테스트를 설계합니다. 실제 결제 한도·비밀값을 코드에 넣지 않습니다.

- [ ] 사용량 미수신과 0 토큰을 같은 상태로 처리하지 않는다.

- [ ] 제공자 청구 한도와 로컬 추정 검사가 다름을 이해한다.

## 14. 핵심 정리

`TokenUsage`는 LLM 응답의 입력·출력 사용량을 보관하고, `ModelPricing`과 `estimate_cost()`는 이를 결정론적인 `Decimal` 추정 비용으로 바꿉니다. `CostBudget`은 같은 통화의 추정 상한을 검사하지만 실제 제공자 결제를 차단하지는 않습니다. 가격표와 사용량 수신 여부를 함께 기록하고, 호출 전에는 보수적인 토큰 상한·제공자 예산 정책으로 비용을 별도로 통제해야 합니다.
