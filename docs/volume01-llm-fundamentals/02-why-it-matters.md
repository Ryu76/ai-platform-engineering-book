# LLM 기초: 왜 필요한가

## 1. 기존 방식의 한계

전통적인 프로그램은 입력 형식을 미리 정하고 조건문으로 처리합니다. 예를 들어 고객 문의를 `배송`, `환불`, `계정`으로 분류하려면 가능한 표현을 계속 추가해야 합니다. "물건이 아직 안 왔어요"와 "배송 상태를 확인하고 싶습니다"는 의미가 비슷하지만 문자열은 다릅니다.

LLM은 문장의 의미와 문맥을 이용해 이런 표현을 처리할 수 있습니다. 다만 LLM은 데이터베이스나 규칙 엔진을 대체하지 않습니다. 날짜 계산, 권한 확인, 결제, 배포처럼 정확성과 감사가 필요한 일은 검증된 코드와 도구가 담당해야 합니다.

## 2. LLM이 해결하는 일

- 자연어 분류, 요약, 변환
- 정해진 형식의 초안 생성
- 검색 결과를 읽고 근거를 정리하는 답변 생성
- 사람의 요청을 도구가 처리할 입력으로 변환하는 보조

## 3. 실무에서 주의할 점

> [!WARNING]
> LLM의 답변은 그럴듯해도 사실과 다를 수 있습니다. 외부 문서와 최신 정보가 필요한 답변은 이후 Volume의 RAG와 출처 표시를 사용합니다.

> [!TIP]
> 첫 실습의 목표는 "좋은 답변"보다 안전한 호출 경계를 만드는 것입니다. 키, Timeout, 오류, 사용량을 먼저 다룹니다.
