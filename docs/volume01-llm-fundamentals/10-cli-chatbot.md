# 안전한 CLI 챗봇

## 1. 학습 목표

이 장을 마치면 콘솔에서 사용자 입력을 받고 LLM 응답을 출력하는 CLI(Command-Line Interface) 챗봇을 실행할 수 있습니다. 시스템 메시지, 성공한 대화 이력, 종료 명령을 구분하고 빈 입력·입력 종료·LLM 오류를 안전하게 처리할 수 있습니다. 또한 실제 키 없이 오프라인 데모와 Mock 단위 테스트로 대화 계약을 확인할 수 있습니다.

## 2. 왜 필요한가

앞 장까지는 한 번의 요청을 보내고 결과를 받았습니다. 실제 대화는 이전 질문과 답변을 다음 요청에 전달해야 문맥을 유지합니다. 그러나 이력을 제한 없이 쌓으면 컨텍스트 윈도우와 비용이 증가하고, 실패한 요청까지 저장하면 모델이 답하지 않은 내용을 대화 사실처럼 보낼 수 있습니다.

이 장의 챗봇은 이후 RAG 검색 결과, Router 결정, Agent 상태를 연결할 가장 작은 사용자 입구입니다. 여기서는 텍스트 대화와 안전한 종료만 다룹니다. 파일 변경, 배포, 메일 발송처럼 위험한 Tool 호출은 구현하지 않습니다.

## 3. 핵심 개념

**대화 이력(conversation history)** 은 다음 요청에 전달할 이전 메시지입니다. `ConversationHistory`는 시스템 메시지 하나와 성공한 사용자·Assistant 쌍만 저장합니다. 기본값은 최근 6개 턴입니다. 새 턴이 한도를 넘으면 가장 오래된 **완료된 쌍**을 제거합니다. 시스템 메시지와 중간 한 턴만 제거하지 않으므로 역할 순서가 깨지지 않습니다.

`/exit`, `/quit`은 모델에 보내지 않는 로컬 종료 명령입니다. 빈 입력도 전송하지 않습니다. 시간 초과·네트워크·응답 형식 오류가 발생하면 원본 예외나 사용자 입력을 출력하지 않고, 오류 종류에 맞는 안내만 표시합니다. 실패한 사용자 메시지는 이력에 기록하지 않으므로 다음 질문에 섞이지 않습니다.

> [!WARNING]
> 콘솔 입력에는 API 키, 회사 문서, 개인정보를 넣지 않습니다. 이 예제는 대화 이력을 메모리에만 보관하지만, 라이브 모드에서는 입력이 선택한 제공자에게 전송됩니다. 오프라인 데모 모드만 네트워크를 사용하지 않습니다.

## 4. 동작 구조

```text
사용자 한 줄 입력
      │
      ├── 빈 입력 ───────────────────────► 안내 출력, 전송하지 않음
      ├── /exit 또는 /quit ──────────────► 로컬 종료, 전송하지 않음
      ▼
ConversationHistory.messages_for(질문)
      │  시스템 + 성공한 최근 턴 + 새 질문
      ▼
ChatCompleter.complete(...)
      │
      ├── LLM 오류/빈 응답 ──────────────► 안전한 안내, 이력 미변경
      ▼
성공 응답
      │
      ▼
사용자·Assistant 쌍 기록(최근 6턴) ────► AI> 응답 출력

--offline-demo ─► OfflineDemoClient ─► 외부 API·네트워크 없음
```

## 5. 실습 환경

이전 장의 프로젝트 가상환경을 그대로 사용합니다.

- `src/ai_platform/llm/chat.py`: 이력 한도, 종료 명령, 오류 안내가 있는 재사용 가능한 콘솔 루프입니다.
- `examples/volume01/chat_cli.py`: `--offline-demo`와 명시적 라이브 모드를 제공하는 실행 파일입니다.
- `tests/unit/test_chat.py`: 입력·출력·LLM 클라이언트를 Mock으로 바꾸어 외부 전송 없이 검사합니다.

```bash
# 실행 위치: WSL Ubuntu 또는 Linux 터미널, 저장소 루트
cd ~/projects/ai-platform-engineering-book
conda env update --file environment.yml --prune
```

이 명령은 가상환경과 검사 도구를 준비합니다. 아래 6.1과 6.2는 API 키·계정·외부 네트워크를 사용하지 않습니다.

## 6. 단계별 실습

### 6.1 오프라인 데모로 콘솔 흐름 실행

```bash
# 실행 위치: WSL Ubuntu 또는 Linux 터미널, 저장소 루트
python examples/volume01/chat_cli.py --offline-demo
```

`사용자>` 프롬프트가 나오면 `RAG는 무엇인가요?`를 입력하고, 다음 줄에 `/exit`을 입력합니다. `--offline-demo`는 마지막 사용자 입력을 표시하는 결정론적 응답기이므로 API 키와 네트워크가 필요 없습니다.

### 6.2 Mock 단위 테스트 실행

```bash
# 실행 위치: WSL Ubuntu 또는 Linux 터미널, 저장소 루트
pytest tests/unit/test_chat.py -q
```

테스트는 성공 이력 저장, 가장 오래된 턴 제거, 빈 입력, EOF, 시간 초과·네트워크 오류의 비밀값 없는 안내, `/exit`과 `/quit` 종료를 확인합니다. 실제 `input()`, 실제 API, 실제 대기 시간을 사용하지 않습니다.

### 6.3 코드의 대화 이력 경계 확인

`run_chat_loop()`은 새 질문을 `messages_for()`로 요청에만 포함하고, `complete()`가 성공한 뒤에만 `record_success()`를 호출합니다.

```python
try:
    response = client.complete(conversation.messages_for(user_content))
except LlmTimeoutError:
    write_output("요청 시간이 초과되었습니다. 잠시 뒤 다시 시도하세요.")
    continue

assistant_content = response.content.strip()
if not assistant_content:
    write_output("제공자가 빈 응답을 반환했습니다. 질문을 다시 확인하거나 잠시 뒤 시도하세요.")
    continue
conversation.record_success(user_content=user_content, assistant_content=assistant_content)
write_output(f"AI> {assistant_content}")
```

이 순서는 실패·빈 응답을 대화 기억으로 오인하지 않게 합니다. 출력은 응답 텍스트만 포함하며 원본 예외, Authorization 헤더, API 키를 표시하지 않습니다.

### 6.4 선택 사항: 자신의 제공자로 라이브 실행

이 단계는 외부 데이터 전송과 비용을 발생시킬 수 있습니다. 실행하지 않아도 앞의 오프라인 데모와 테스트로 이 장의 핵심 계약을 검증할 수 있습니다.

```bash
# 실행 위치: WSL Ubuntu 또는 Linux 터미널, 저장소 루트
cp .env.example .env
# .env에 본인 값으로 LLM_MODEL, OPENAI_API_KEY를 설정
set -a
. ./.env
set +a
python examples/volume01/chat_cli.py
```

`--offline-demo` 없이 실행하면 환경 설정을 읽고 한 질문마다 명시적으로 `LlmClient.complete()`를 호출합니다. `.env`를 Git에 추가하지 않습니다. `LLM_BASE_URL`을 변경하는 경우에도 신뢰할 수 있는 제공자 주소만 사용합니다.

## 7. 코드 설명

`ChatCompleter` Protocol은 콘솔 루프가 `complete(messages)`만 필요하다는 사실을 드러냅니다. 따라서 `LlmClient`와 테스트용 `ScriptedClient`를 같은 루프에 주입할 수 있습니다. 이는 외부 API 없는 재현 가능한 테스트 경계입니다.

`ConversationHistory.messages_for()`는 시스템, 이전 성공 턴, 새 사용자 메시지를 새 리스트로 만듭니다. `record_success()`는 사용자와 Assistant 메시지를 쌍으로 넣고 한도를 넘을 때 `pop(0)`으로 가장 오래된 쌍을 제거합니다. 이 예제는 토큰 수를 정확히 계산하지 않습니다. 실제 서비스는 모델 토크나이저, 사용량, 비용 상한을 Volume 01의 09장 계약과 함께 사용해야 합니다.

`examples/volume01/chat_cli.py`의 기본 모드는 환경에서만 키를 읽습니다. `--offline-demo`는 설정을 읽지 않으며 `offline-demo`라는 모델명을 가진 고정 응답을 만듭니다. 데모 결과의 사용량 `0`은 제공자 사용량이 아니라 네트워크를 사용하지 않았다는 뜻입니다.

## 8. 정상 실행 결과

오프라인 데모에서 `RAG는 무엇인가요?`, `/exit`을 순서대로 입력하면 다음과 유사한 결과가 표시됩니다.

```text
AI 업무 처리 플랫폼 챗봇입니다. 종료하려면 /exit 또는 /quit을 입력하세요.
사용자> RAG는 무엇인가요?
AI> 오프라인 데모 응답: 'RAG는 무엇인가요?' 요청을 기록했습니다.
사용자> /exit
대화를 마칩니다.
```

단위 테스트의 정상 결과는 다음과 유사합니다.

```text
8 passed
```

## 9. 오류 해결

| 증상 | 원인 확인 | 해결 |
|---|---|---|
| `빈 메시지는 전송하지 않았습니다` | 공백만 입력했습니다. | 질문을 입력하거나 `/exit`으로 종료합니다. |
| `입력이 종료되어 대화를 마칩니다` | Ctrl+D, 파이프 입력 종료 또는 입력 스트림 종료입니다. | 정상 종료 안내입니다. 새 터미널에서 다시 시작할 수 있습니다. |
| `LLM 설정을 확인하세요` | 라이브 모드의 모델명·키가 없거나 시간 제한 값이 잘못되었습니다. | `.env.example`을 참고해 `.env`를 설정하고, 키를 출력·커밋하지 않습니다. 오프라인 학습에는 `--offline-demo`를 사용합니다. |
| `제공자 연결에 실패했습니다` | 네트워크, DNS, 제공자 주소 또는 제공자 상태 문제일 수 있습니다. | `LLM_BASE_URL`과 네트워크를 확인합니다. 원본 오류·키를 로그에 복사하지 않습니다. |
| 이전 질문을 너무 많이 기억하지 못함 | 기본 이력 한도는 최근 6개 성공 턴입니다. | 이력 한도와 토큰·비용 정책을 함께 설계합니다. 무제한 이력으로 바꾸지 않습니다. |
| 응답이 반복되거나 부적절함 | 모델 생성 특성과 시스템 지시문을 확인해야 합니다. | system prompt와 생성 파라미터를 06장에서 조정하고, 중요한 답변은 근거로 검토합니다. |

## 10. 응용 실습

1. `ConversationHistory(max_turns=2)`를 사용해 세 번 질문하고, 네 번째 요청에 어떤 메시지가 전달되는지 Mock 테스트로 확인합니다.
2. `/help`를 로컬 명령으로 추가해 종료 명령, 대화 이력 한도, 외부 전송 경고를 출력합니다. `/help` 자체는 모델에 보내지 않도록 테스트합니다.
3. `LlmResponse.usage`가 있는 라이브 응답에서 모델명·토큰 수·비용 추정만 기록하는 함수를 설계합니다. API 키, 전체 사용자 입력, Assistant 원문은 기록하지 않습니다.

## 11. 실무 적용

운영용 CLI 또는 Gateway는 사용자별 세션 ID, 이력 보존 기간, 최대 토큰, 요청 속도, 비용 예산을 정책으로 관리해야 합니다. 메모리 안 이력은 프로세스 종료 시 사라지고 여러 인스턴스 사이에서 공유되지 않습니다. 영속화가 필요하면 암호화, 접근 제어, 삭제 기한, 개인정보 정책을 먼저 설계합니다.

사용자 입력은 시스템 지시문이 아닙니다. 이후 RAG에서 가져온 문서와 Tool 결과도 신뢰되지 않은 데이터로 구분합니다. Tool 호출·파일 접근·배포 요청에는 별도 권한과 사람 승인을 둡니다. Volume 02의 Prompt Injection 방어, Volume 05의 인용, Volume 09의 상태·체크포인트가 이 작은 CLI 경계를 확장합니다.

## 12. 과제

- **기본:** 성공한 대화만 이력에 저장해야 하는 이유를 설명합니다.
- **응용:** 대화 이력의 턴 한도와 컨텍스트 윈도우·토큰 비용의 관계를 설명합니다.
- **심화:** 여러 사용자 세션을 저장할 때 필요한 세션 격리, 접근 제어, 보존 기간, 삭제 승인 정책과 이를 검증할 Mock 테스트를 설계합니다.

## 14. 핵심 정리

CLI 챗봇은 사용자 입력을 시스템 메시지·성공 이력과 함께 LLM에 전달하는 최소 사용자 경계입니다. 이 프로젝트의 `ConversationHistory`는 최근 성공 턴만 제한적으로 보관하고, 오류·빈 응답은 기억하지 않습니다. `/exit`과 `/quit`, 빈 입력, EOF, LLM 오류는 모델에 불필요하게 전송하지 않으며, `--offline-demo`와 Mock 테스트로 실제 키·네트워크 없이 전체 흐름을 검증할 수 있습니다.
